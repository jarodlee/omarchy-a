# Omarchy 本机服务首页

iPad 浏览器打开 `http://127.0.0.1/` 或 `http://localhost/`；
同一局域网当前使用 `http://192.168.1.207/`。应用菜单另有“服务首页”快捷方式。
局域网地址随设备网络变化，本机回环地址不变。没有增加公网首页域名。

入口包含 AI 错题本、知识图谱、学习诊断、学习档案/历史、账号同步和电池监测。
学习网站沿用已有 HTTPS 地址和账号；错题本另有局域网直达入口。
电池链接及错题本内网入口根据访问首页时的主机名生成端口地址，不将办公室 IP 写死在页面中。
知识图谱登录使用已配置的 HTTPS 来源，不通过不匹配的 HTTP 地址绕开账号保护。

HTML、样式、图标和交互脚本在一个文件中，无外部字体、CDN 或构建依赖。
页面适配手机、平板及明暗主题。首页只展示链接与本机健康状态，不读取或显示学习记录、
密码、会话、通道密钥等。域名入口仍需要联网，AI 分析需要 MacMini 和 Cindy 在线。

部署：将 `omarchy-home.html` 安装为 `/opt/omarchy-home/index.html`，
将 `omarchy-home.py` 放在同一目录，root 持有文件、普通服务用户只读。
创建无登录权限的系统用户 `omarchy-home`，安装 `omarchy-home.service` 后运行
`start-omarchy-home.sh`，验证并启用开机启动。
`omarchy-service-home.desktop` 放入 tablet 用户的 `.local/share/applications/`，由该用户持有。

服务监听 IPv4 80 端口；仅授予绑定低端口的能力，不以 root 运行。
systemd 将网络范围限制为本机及私有局域网；不增加 Cloudflare 公网入口。
内存上限 48 MB，实测约 16 MB。服务无数据库和写入 API。
健康检查为 `/health`，`/api/status` 只请求固定回环健康地址，缓存十秒；
前端每三十秒刷新。状态表示本机进程健康，不表示公网域名或 AI 模型一定在线。

验证：iPad 回环和 Mac 局域网 HTTP 访问成功，三个底层服务健康；
浏览器检查全部入口、动态局域网链接、状态与页面显示；服务重启后恢复，开机启动已启用。
既有错题本、知识图谱和电池服务继续运行。

本项为可选部署。回退时停用 `omarchy-home.service` 并移除该快捷方式即可，
不删除其他服务与记录。CHANGELOG 未修改；拟议说明：为本机学习服务增加统一导航首页。
